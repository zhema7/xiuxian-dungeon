## 数值校准（关键教训）
- 战力换算若用**线性**玩家曲线，会系统性低估中后期玩家（装备/心法/天赋是复利），导致 NPC 倍率虚高打满上限。
  改二次项 `atk = 12 + lv*4.8 + lv²*0.16` 后：练气 0.95 / 金丹 1.19 / 化神 1.37，曲线合理
- 倍率公式用 `0.5 + 0.45 × ratio^0.75` 压缩，上限 2.2；真实玩家属性走 `calcStats(state)`，估算仅兜底
- NPC 攻击基础由 `14 + 境界*20 + 等级*4.5` 下调到 `12 + 境界*15 + 等级*3.2`（贴近玩家含装备曲线），
  强度差交给经历/道行/装备/功法拉，避免队友输出碾压玩家

# NPC 与宗门全量盘点（2026-09-09 晚，纯调研不改码）

产出：`docs/project-review/2026-09-09-NPC与宗门系统现状盘点.md`

## 结论
功能量足（24 模块 ~9650 行），**结构性债务 > 功能缺口**：两套弟子集合、两套建筑升级、四套 NPC 模型互不相通。

## 关键事实（脚本核对）
- 固定 NPC **20 位**（city6/sect6/world4/home2/arena2），**全部共用 `npc_junior` 贴图**（靠 npc-sprite-gen 按 appearanceSeed 程序化生成）；STORIES 仅 **5 条**（覆盖 5/20）
- 程序化 NPC：MAX_ACTIVE_NPCS=25、NPC_REFRESH_DISTANCE=600、每次补员 2
- 灵兽 8 物种 / 4 稀有度 / 6 元素
- 宗门：14 建筑、6 资源、建宗需 10000 灵石 + 金丹期
- AI 宗门 **6 个**（WorldScene:5081 循环 6 次）、5 性格、7 外交行动、每 5 分钟 tick
- 场景分工：WorldScene 吃掉宗门全部（建宗/建筑/职位/门规/外交/战争/AI宗门）；SectScene 只有场景渲染+生产+自有建造升级

## 发现的问题（按严重度）
1. **P0 弟子双轨**：`sect.disciples: Disciple[]`（disciple-data.ts:69）vs `state.disciples: DiscipleData[]`（disciple-system.ts:9）。
   两套类型两套写入（前者由 disciple-system:160 / ui.ts:260 / SectScene:1489,1548 写；后者由 disciple-system:132 写）。
   **宗门战力两套口径**：diplomacy.ts:66 用 sect.disciples.length，sect-war.ts:53 与 annual-events.ts:65 用 state.disciples。
   删除不同步——diplomacy.ts:369 只从 sect.disciples 删战损。
2. **P1 建筑升级双实现**：SectScene.ts:1253 自有 upgradeBuilding（走 sect-data.buildingUpgradeCost），
   与 sect-building-v2.ts:62 另一套。**SectScene 没有 import sect-building-v2**。
3. **P1 修为档案只覆盖程序化 NPC**：固定 NPC 靠 sectNpcProfile() 派生不入库；弟子两套都无装备功法（战力是纯公式值）。
4. P2：20 位固定 NPC 同贴图；故事线 5/20。
5. P2 flaky：tests/npc-diplomacy.test.ts（updateNpcGrowth 用 Date.now()/60000 播种）。

## 建议顺序
弟子合轨（Disciple 为源，DiscipleData 降派生）→ 修为档案下沉弟子 → 建筑升级合并 → 固定 NPC 补故事线 → flaky 修复。
