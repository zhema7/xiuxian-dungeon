## 1. 验收目标与冻结边界

### 1.1 本轮目标

验证动态随机套的 **Palette V1** 为一个可追溯、可重复计算的纯派生视觉层：在 `schemaVersion=3`、`generatorVersion=2` 的动态随机套上，攻击、神通、模块 VFX、`dageng`、雷链，以及首中后派生的子剑/火弹整条视觉链，均使用其**发起 source 对应的同一色板**。

本计划只验收颜色来源、色板传播、动画资源接入与安全降级；不新增或重定义任何套装、数值、伤害、冷却、目标、件数阈值、触发次数、连锁规则或存档迁移规则。

### 1.2 不可变合同

以下为本轮 P0 不变量。实现、测试夹具和人工验收均不得以 Palette V1 为由改变它们：

1. **纯派生：** Palette V1 只能由当前动态 v3/generator v2 套装及其实际 source 身份确定；不得依赖 `Math.random`、时间、帧率、全局状态、加载顺序或一次性运行时缓存的偶然值。
2. **同源传播：** 一个攻击或神通 source 触发的所有后续视觉节点，继承该 root source 的 Palette V1；不得在模块、雷链、子剑或火弹节点重新抽色、混入另一 source 的颜色，或退回全局默认色。
3. **攻击/神通分源：** attack source 使用自己的色板；art source 使用自己的色板。二者同时存在、轮换触发或只有其中一方 source 改变时，另一方的视觉色板不得被带动。
4. **旧内容保色：** 静态套装、读取的 v2 记录和 legacy 记录继续走各自既有原色路径；不得因读取、注册、装备、攻击、神通、保存或重载而注入 Palette V1。
5. **战斗与套装合同不变：** Palette 字段以外的事件数量、触发时机、伤害输入/输出、倍率、冷却、目标、递归保护、装备阈值、联动开关和存档语义必须与当前批准基线一致。
6. **动画不虚报：** 只有资源实际存在、已被真实运行时注册、且实例实际播放多个注册帧时，才可标记为“序列帧/已动画化”。仅有文件名、单帧资源、未注册帧或失败回退均不能算动画化。
7. **缺帧安全：** `mod`、`fx`、`bolt`、`proj` 任一类帧缺失，或其注册无效时，只能走已注册的静态回退或无视觉回退；不得崩溃、报未捕获异常、显示坏资源、错误复用无关 source 的颜色，或声称已动画化。

### 1.3 范围与非范围

| 在范围内 | 明确不在范围内 |
|---|---|
| 动态随机套 v3 / generator v2 的 Palette V1 派生与身份追踪 | 修改生成器、套装数据、数值、伤害、冷却、掉率、AI 或战斗规则 |
| attack / art source 分流与色板继承 | 将 v2/legacy 或静态内容升级为 Palette V1 |
| 攻击、神通、模块 VFX、`dageng`、雷链、首中子剑/火弹全链路颜色 | 新建、替换或补齐生产美术资源 |
| 真实 `slash` / `sword_proj` 序列帧注册、播放与缺帧降级验证 | 把存在于目录但未真实注册的帧宣称为动画 |
| 可读性、减闪、高对比、浏览器手工烟雾与自动化质量门 | 构建、发布、提交、部署或干扰用户正在进行的手工测试 |

`dageng`、雷链、子剑与火弹均沿用任务命名；实际测试必须以工程交付的真实注册 key、别名和事件类型为准，不得在测试中另造白名单。

## 2. 必须交付的可观察证据接口

独立 QA 不以截图、资源目录或开发口头说明替代可验证事实。工程交付时必须提供测试可读的观察接口（字段名可映射，语义不可省略）。

### 2.1 Palette V1 观察记录

每次生成、解析或视觉生成至少能导出下列等价信息：

```ts
interface PaletteTrace {
  paletteVersion: 'V1'
  paletteIdentity: string                 // 由 v3/generator v2 的正式身份字段规范化而来
  paletteSignature: string                // 可比较的规范化颜色/角色签名，非随机实例 ID
  sourceKind: 'attack' | 'art' | string   // 使用工程实际 source 枚举
  sourceId: string
  rootEventId?: string
  eventId?: string
  parentEventId?: string
  visualKind: 'attack' | 'art' | 'module' | 'dageng' | 'thunder-chain' | 'child-sword' | 'fireball' | string
  renderMode: 'registered-sequence' | 'static-fallback' | 'none-fallback'
  resourceKey?: string
  animationRegistrationId?: string
  fallbackReason?: 'missing-frame' | 'unregistered-frame' | 'unsupported-resource' | string
}
```

要求：

- `paletteIdentity` 必须说明哪些正式 v3/generator v2 身份字段参与派生；它不能只是每次运行新建的对象 ID。
- `paletteSignature` 必须可在无渲染器环境比较；颜色格式须先规范化（例如规范 HEX 或线性色彩值），避免格式差异掩盖实际变化。
- 每个派生节点必须保留 `rootEventId` / `parentEventId` 或等价链路关系，以便审计同源色板是否贯穿整链。
- 静态、v2、legacy 路径必须能报告为“原色路径/非 V1”，而不是伪造一条 `paletteVersion='V1'` 记录。

### 2.2 资源与动画注册清单

工程必须从**实际资源加载/动画注册表**导出可比较清单，至少包含：资源 key、帧顺序、帧数、每帧解析结果、注册 animation key、调用方以及回退资源/无视觉策略。

特别要求：

- 对已有 `slash`、`sword_proj` 序列，只有同时满足“帧资源存在”“帧已真实注册”“运行实例引用该注册 animation”“运行中可观察到至少两个不同注册帧”四项，才记录 `renderMode='registered-sequence'`。
- 目录中有帧、但没有注册；注册存在、但运行实例没有使用；或只解析出一个帧，均不得作为“已动画化”证据。
- 对 `mod`、`fx`、`bolt`、`proj`，清单必须给出逐类的正常资源及回退策略；测试不得通过删除用户正在使用的资源或操作用户浏览器来制造缺失条件，应使用工程提供的测试注入/虚拟加载器。

### 2.3 保持战斗合同的基线快照

工程需随交付提供 Palette 改动前后的受控事件快照。比较时仅允许新增/变化 Palette 与渲染诊断字段；其余字段必须一致，包括：套装激活状态、route/source 选择、伤害、倍率、冷却、命中/连锁数量、目标、事件顺序、递归深度、卸装清理和存档语义。

没有可比较的当前合同快照时，`PAL-P0-09` 不能签收；QA 不会自行猜测既有战斗数值。

## 5. 动画资源与缺帧降级专项规则

### 5.1 `slash` / `sword_proj`：存在且注册才接入

对每一个工程实际注册为 `slash` 或 `sword_proj` 的候选序列，按以下顺序执行：

1. 从真实清单取到资源 key、帧列表、帧顺序、注册 animation key 和调用 source；
2. 逐帧解析，确认帧存在且可由当前加载器读取；
3. 确认动画注册表中存在同一 animation key，且帧列表与实际清单一致；
4. 用对应攻击/神通实际生成一个实例，确认实例调用的是该注册 key；
5. 在运行 trace 或帧捕获中确认至少两个不同已注册帧实际出现；
6. 同时确认每个帧/实例携带正确的 root source Palette V1，而不是因为序列播放回退到固定色。

**允许的结论只有两种：**

- `已接入序列帧`：满足以上六步，记录证据；
- `安全降级（非动画）`：缺帧、无注册、单帧、调用方未接入或运行时无法播放时，使用真实注册的静态/无视觉回退并记录原因。

不得写“已动画化/已接入序列帧”，除非证据同时证明资源存在**且**注册有效**且**运行实际播放。

### 5.2 `mod` / `fx` / `bolt` / `proj`：逐类缺失矩阵

每一类至少执行“该类单独缺失”和“与其他类同时缺失”两种测试。测试注入不得删除真实文件、修改用户资源或干扰用户的浏览器会话。

| 缺失类别 | 必检安全行为 | 禁止行为 |
|---|---|---|
| `mod` | 模块视觉走注册静态回退或无视觉回退；逻辑事件与 source palette trace 完整 | 抛错、改用无关模块颜色、声称模块已动画化 |
| `fx` | 基础效果安全降级；若仍显示，颜色来自原 root source | 坏资源、黑/白占位误作成功特效、切换全局默认色 |
| `bolt` | 雷链/弹体视觉可降级但链路逻辑保持既有合同 | 因资源缺失改变弹跳、伤害、冷却、目标或把静态帧标为序列 |
| `proj` | 子剑/火弹投射物安全降级；父子链与战斗结果保持基线 | 丢失父子关系、子体重新派色、崩溃或虚报动画 |

回退渲染若实际存在，仍必须保持 root source 的可追溯色板；若没有任何可用渲染资源，则应明确标记 `none-fallback`，而非伪造成功 VFX。

## 8. 质量门与明确 FAIL 条件

### 8.1 PASS

仅当以下条件同时满足，QA 才可建议将文档状态从“待工程交付/待独立签收”更新为独立 PASS：

- `PAL-P0-01` 至 `PAL-P0-14` 全部通过，且每项有可复查的 trace、资源注册或回退证据；
- 两次全量 `npm test` 均通过，发现数一致，无 flaky、`.only`、未批准 skip 或重试掩盖；
- `validate:data` 与 `typecheck` 均退出码 0；
- 浏览器 M-01 至 M-08 在隔离 QA 会话中通过，控制台无相关未捕获错误；
- `slash` / `sword_proj` 的动画结论以“资源存在且注册且实际播放”为准；缺帧项均有真实安全降级证据；
- 静态/v2/legacy 原色、当前套装合同和战斗合同均无回归；
- 高对比和减闪证据完整，无未关闭 P0 缺陷。

### 8.2 CONCERNS

仅当全部 P0 已通过、但存在不改变功能正确性的已登记非阻断观察项时使用，例如经审批的美术偏好优化或未来资源补齐建议。资源尚未交付、测试未执行、注册清单缺失或浏览器烟雾未完成时，不能以 CONCERNS 视为放行。

### 8.3 FAIL

以下任一项在工程交付后的独立验收中命中，即为 **FAIL / 未达 QA**：

1. 同一 Palette V1 身份不能稳定复现，或派生使用随机、时间、帧率、加载顺序等非合同输入；
2. attack 与 art source 串色，或 source 改动污染无关通道；
3. 模块 VFX、`dageng`、雷链、首中子剑/火弹任一节点没有继承 root source 色板；
4. Palette V1 改变任何既有套装/战斗合同字段或行为；
5. 静态、v2 或 legacy 路径颜色变化、错误进入 V1，或兼容读取被重骰/强迁移；
6. `slash` / `sword_proj` 未满足“存在且注册且实际播放”仍被标为动画，或已注册可用序列未正确接入；
7. 任一 `mod`/`fx`/`bolt`/`proj` 缺帧导致崩溃、未捕获错误、坏资源、错误 source 色、战斗变化或动画虚报；
8. 高对比基线缺失/未达门槛、关键视觉不可读，或同一色板链出现随机高频闪变；
9. P0 自动化缺失、测试信号被 skip/only/retry/选择性运行掩盖，或任一强制命令失败/两次全量结果不稳定；
10. 浏览器烟雾出现可复现的 P0 视觉、资源、链路或战斗回归。

工程尚未提供观察接口、真实注册清单、指定夹具、缺帧注入、基线快照或可执行测试时，当前状态保持“待工程交付/待独立签收”；一旦要求独立签收而上述 P0 证据仍缺失，则按 FAIL 处理，不能默认放行。
