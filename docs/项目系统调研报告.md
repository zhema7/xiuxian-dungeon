### 1.4 敌人 AI 逻辑详解

**核心函数：`Enemy.update(ctx: CombatCtx)`（`src/entities.ts` 第 196-308 行）**

AI 状态机流转：

```
idle（游荡） → aggro触发 → chase（追击） → 进入攻击距离 → windup（蓄力）
                                                          ↓
                                                      造成伤害
                                                          ↓
                                                      回到 chase
```

**状态转移逻辑：**

1. **idle 游荡**（无仇恨时）：
   - 每 1200~3000ms 随机改变方向
   - 45% 概率静止不动
   - 移动速度为正常速度的 35%

2. **aggro 仇恨触发**：
   - 距离 < 210px 或 受伤后进入仇恨
   - 仇恨后进入 chase 状态追击玩家

3. **卡墙脱困机制**：
   - 每 350ms 检测位移量
   - 追击中位移 < 3px 判定为卡墙
   - 随机侧移 450ms 脱困

4. **近战攻击（melee/boss常态）**：
   - 攻击距离：普通怪 28px，Boss 46px
   - 蓄力时间：普通怪 320ms，Boss 420ms
   - 蓄力时身体发黄（`0xffe08a` tint）
   - 蓄力结束后若仍在范围内则造成伤害

5. **远程攻击（ranged）**：
   - 攻击距离由 `cfg.range` 决定（默认 160px）
   - 距离 < 70px 时后退拉开距离
   - 距离在范围内且冷却就绪时进入蓄力（420ms）
   - 蓄力结束后发射投射物（调用 `ctx.spawnProj`）
   - 距离 > range 时追击靠近

6. **Boss 冲撞（dash）**：
   - 冷却 6500ms，距离 70~240px 触发
   - 冲撞速度 280，持续 520ms
   - 冲撞时身体发红（`0xff6666` tint）
   - 冲撞中接触玩家造成 1.4 倍伤害
   - 冲撞结束后回到 chase 状态

7. **减速效果**：
   - 受到冰霜类效果时速度减半
   - 身体变蓝（`0x9fd8ff` tint）

**敌人使用技能的方式**：敌人的"技能"本质上是其 AI 类型决定的攻击模式——近战直接挥砍，远程发射投射物，Boss 额外有冲撞技能。所有伤害结算均通过 `CombatCtx` 回调到 `DungeonScene.damagePlayer()`。

### 2.3 境界与数值的关系

**属性计算公式（`src/effects.ts` calcStats 函数）**

```typescript
function calcStats(s: GameState): Stats {
  const c = CLASSES[s.classId]        // 职业基础
  const lv = s.level - 1              // 等级成长
  const m = aggregateMods(s)          // 装备/套装/心法/天赋修饰
  const realmMult = 1 + REALM_STAT_BONUS * s.realm  // 境界倍率

  return {
    maxHp: Math.round((c.base.hp + c.growth.hp * lv + m.maxHp) * (1 + m.hpPct) * realmMult),
    atk:   Math.round((c.base.atk + c.growth.atk * lv + m.atk)   * (1 + m.atkPct) * realmMult),
    def:   Math.round((c.base.def + c.growth.def * lv + m.def)   * (1 + m.defPct) * realmMult),
    speed: c.base.speed + m.speed,          // 速度不受境界倍率影响
    crit:  c.base.crit + m.crit,             // 暴击不受境界倍率影响
    aspd:  Math.min(0.4, m.aspd),            // 攻速上限 40%
    lifesteal: Math.min(0.35, m.lifesteal),  // 吸血上限 35%
    skillPct: m.skillPct,                    // 技伤
    cdPct: Math.min(0.5, m.cdPct),           // 冷却缩减上限 50%
  }
}
```

**化神期数据特点**：
- 解锁等级：45 级
- 突破所需：6 颗突破石
- 属性加成：基础攻击/防御/气血 +48%（境界索引 4 × 12%）
- 是游戏中第 5 重境界，仅次于炼虚期

**数值计算优先级（从内到外）**：
1. 职业基础值 + 等级成长值 + 装备/词缀固定值
2. × 百分比加成（atkPct/defPct/hpPct）
3. × 境界倍率（realmMult）

### 3.4 套装效果生效机制

**套装效果分层门禁（`src/effects.ts`）**

1. **数值修饰层（mods）**：
   - 函数：`isSetNumericBonusActive(pieceCount, bonus)`
   - 规则：`pieceCount >= bonus.count` 即生效
   - 多个 setId 的数值层独立叠加

2. **表现能力层（attackMode/artMode/transformId/vfxRecipe 等）**：
   - 函数：`isSetPresentationBonusActive(pieceCount, bonus)`
   - 规则：必须是 4 件或 6 件条目，且 `pieceCount >= bonus.count`
   - 2 件条目即使配置了表现字段也会被运行时拒绝

3. **胜出选择（多个套装时）**：
   - 函数：`selectSetAttackSource()` / `selectSetArtSource()`
   - 规则：高件数优先；件数相同则按 setId 词典序
   - 攻击模式和神通模式独立选择胜出源

**攻击模式解析优先级**：
```
套装攻击模式（4件/6件） > 已装配招式（职业匹配） > 职业默认招式
```
函数：`resolveAttackMode(s: GameState): AttackMode`

**神通模式解析优先级**：
```
套装神通（4件/6件） > 已装配神通（职业匹配） > 无神通
```
函数：`resolveSetArtOverride(s: GameState): SetArtOverride | null`

### 3.5 技能系统

**技能装配槽位（SkillSlots）**：

```

```

### 3.6 首中联动机制（Controlled Hit Linkage）

v3 系统引入的受控首击联动机制，是套装效果的进阶形式：

| Recipe ID | 对应攻击模式 | 效果 |
|-----------|-------------|------|
| flying_sword_first_hit_split | flying_sword_burst | 首击分裂为 2 发小飞剑，伤害 40%，CD 800ms |
| giant_sword_first_hit_fire_bolt | giant_sword | 首击触发 1 发火弹，伤害 40%，CD 1200ms |

**关键约束**：
- 仅在 4/6 件套装条目中生效
- 联动属于攻击源，但大庚剑阵（dageng）硬禁用联动
- 装备变动时通过 epoch 机制失效旧投射物的联动权限

### 4.3 spawnTableFor 函数详解

**函数签名**（`src/data.ts` 第 368-386 行）：
```typescript
export function spawnTableFor(floor: number): SpawnEntry[]
```

**返回值类型**：
```typescript
type SpawnEntry = [string, number, number]  // [怪物ID, 最小数量, 最大数量]
```

**生成逻辑**：

1. **1~6 层**：直接读 `FLOOR_SPAWNS[floor]` 固定配置

2. **7 层及以上（无尽妖域）**：动态生成
   - `depth = floor - 6`（妖域内深度）
   
3. **Boss 层（每 3 层）**：
   - 条件：`depth % 3 === 0`
   - Boss 轮换：`['boss', 'boss2', 'boss3'][Math.floor(depth / 3) % 3]`
   - 小怪配置：`[eagle 1~2, wraith 1~2, moth 0~1]`

4. **普通层**：
   - 基础怪：slime(1~2), bat(1~2+extra), spitter(1~2), wraith(1+extra ~ 2+extra), flower(0~1+min(2,extra)), tortoise(1~1+extra)
   - `extra = min(3, floor(depth / 2))`——随深度增加怪物数量
   - depth >= 3：加入 eagle(1~1+extra)
   - depth >= 5：加入 moth(1~1+min(2,extra))
   - depth >= 7：加入 golem(1~1)

### 4.4 难度递增机制

**楼层难度缩放（spawnFloor 内计算）**：
```typescript
const scale = 1 + (this.floor - 1) * 0.3
```
- 每层怪物气血 +30%（`maxHp = cfg.hp * scale`）
- 每层攻击 +6%（`atk = cfg.atk * (0.8 + scale * 0.2)`）
- 每层防御 +2（`def = cfg.def + floor((scale - 1) * 2)`）
- 每层经验 +30%（`exp = cfg.exp * scale`）

**难度选项加成（DifficultyDef）**：

| 难度 | 怪物HP | 怪物ATK | 经验倍率 | 金币倍率 | 装备楼层加成 | 精英率加成 |
|------|--------|---------|----------|----------|-------------|-----------|
| 普通 | ×1.0 | ×1.0 | ×1.0 | ×1.0 | +0 | +0% |
| 困难 | ×1.6 | ×1.3 | ×1.4 | ×1.5 | +2 | +10% |
| 炼狱 | ×2.5 | ×1.7 | ×2.0 | ×2.2 | +4 | +20% |

**精英怪机制**：
- 60% 基础概率 + 难度加成，晋升一只普通怪为精英
- 精英属性：HP ×1.6，ATK ×1.4，经验 ×2
- 精英体型 ×1.3，金色 tint，必掉装备
- 名称前缀「精英·」

**刷怪密度**：
- 大地图刷怪密度 +50%（`Math.ceil(randInt(min, max) * 1.5)`）

### 4.5 无尽妖域存档机制

- `syCheckpoint`：下次进入的起始层（默认 7）
- `syMaxDepth`：历史最深层（榜单用）
- 每通关一个 Boss 层（depth % 3 == 0）可选择「存档撤离」
- 撤离后保留全部收获，下次从下一层继续

### 5.5 伤害结算流程

**玩家攻击敌人（dealDamage，第 961-971 行）**：

```typescript
private dealDamage(e: Enemy, mult: number, stats: Stats, isSkill: boolean, fromX?, fromY?)
  ├─ 计算最终倍率：mult × (isSkill ? 1 + skillPct : 1)
  ├─ calcDamage(atk × buffAtkPct, finalMult, crit, def, rng)
  │   ├─ 暴击判定：rng() < critRate → 伤害 ×1.6
  │   ├─ 浮动：×(0.9 ~ 1.1)
  │   └─ 最终伤害：max(1, round(raw - def))
  ├─ enemy.takeDamage(dmg, fromX, fromY)
  │   ├─ hp -= dmg
  │   ├─ 受击闪白（70ms）
  │   ├─ 击退：普通怪 70px，Boss 20px
  │   └─ 死亡判定 → die()
  ├─ 飘字显示伤害（暴击金色）
  ├─ 吸血回复：dmg × lifesteal
  └─ 死亡处理 → onEnemyKilled(e)
```

**敌人攻击玩家（damagePlayer，第 1747-1774 行）**：

private damagePlayer(rawAtk: number, fromX: number, fromY: number)

### 设计要点

1. **敌人 AI 设计简洁高效**：状态机 + 计时器驱动，三种 AI 类型（melee/ranged/boss）覆盖所有怪物，Boss 增加冲撞技能丰富战斗节奏。

2. **套装系统分层清晰**：数值层（2件起）与表现层（4/6件）严格分离，多个套装可叠加数值但表现能力唯一胜出，避免混乱。

3. **无尽模式难度曲线**：采用「楼层线性缩放 + 怪物种类逐步解锁 + 每 3 层 Boss 轮换」的设计，既有渐进感又有阶段性挑战。

4. **攻击模式可扩展性**：AttackMode 枚举 + 条件分发的设计，便于新增招式/套装形态，v4 Kit 系统进一步通过 executor + scene-adapter 旁路扩展。

5. **伤害管线统一**：玩家打敌人和敌人打玩家走两条独立管线，但核心计算逻辑一致（攻击×倍率-防御，暴击×1.6，±10%浮动）。
