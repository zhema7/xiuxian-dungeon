# 《修仙与地下城》技术方案

> 版本：v0.2（2026-08 已按实现现状同步）
> 目标：Web 端（PC + 移动浏览器）、2D 像素、竖屏、实时战斗 Roguelike
>
> 说明：本文档既描述技术选型与架构设计，也标注当前实际落地状态。
> 每节用「现状」描述已实现内容；「待办」为设计文档原规划但尚未落地项，汇总见文末差异清单。

## 二、总体架构

```
┌────────────────────────────────────────────┐
│                 UI 层（DOM）                 │  HUD / 背包 / 角色 / 坊市 / 对话 / 天赋
├────────────────────────────────────────────┤
│   场景层（Phaser Scenes）                    │  Boot → Title → Town(洞府) → Dungeon
├────────────────────────────────────────────┤
│   玩法系统层（纯 TS 模块，多数不依赖 Phaser）   │  战斗 / 掉落 / 装备 / 功法 / 天赋 / NPC / AI
├────────────────────────────────────────────┤
│   数据层：Config Tables(JSON) + 存档(localStorage) │
├────────────────────────────────────────────┤
│   引擎层：Phaser（渲染 / 输入 / 物理 / 音频）    │
└────────────────────────────────────────────┘
```

**现状**：
- 玩法核心已解耦：`core.ts`（随机数/伤害/掉落/经验/装备 roll）、`effects.ts`（修饰聚合与攻击模式解析）、`skills.ts` / `talents.ts` / `favor.ts` / `levelgen.ts` / `lore.ts` 均为纯 TS，不 import Phaser。
- 实体层 `entities.ts` 是 Phaser 绑定（`Player` 类持有 `Phaser.Physics.Arcade.Sprite`），非设计文档的「轻 ECS 组件式」——采用传统 class 实现，够用未重构。

**待办**：设计文档规划的独立 `src/core/` 分层目录与独立 Store 事件总线未落地，当前为扁平结构（见第八节目录）。

## 三、运行模式与画面适配

- 设计分辨率 **360×640**（设计文档原写 750×1334，实际以 360×640 为基准），`Phaser.Scale.FIT` + `CENTER_BOTH` 居中自适应。
- `pixelArt: true`，关闭抗锯齿；CSS `image-rendering: pixelated` 保证像素锐利。
- 输入统一抽象 `InputPort`（`input.ts`）：移动端虚拟摇杆 + DOM 大按钮；PC 映射 WASD/方向键 + J/K/B/E/L 键——同一套指令队列，场景每帧 `poll()` + `consume*()` 消费。
- 刘海屏适配：`viewport-fit=cover` + `env(safe-area-inset-*)`。
- 目标帧率 60fps（未做低端机动态降档，见待办）。

## 四、数据驱动配置设计（核心）

所有内容进 JSON 表，构建期 `scripts/validate-data.mjs` 校验（字段完整性 + 引用悬空 + 枚举合法），失败即非零退出；`predev` / `prebuild` 自动执行。

```
src/data/
  classes.json     职业定义（基础/成长/默认招式/素材朝向修正 dirRemap）
  monsters.json    怪物（属性 / AI 行为模板 / 掉落）
  floors.json      1~6 层固定刷怪表（7 层起由 data.ts 动态生成）
  items.json       装备基座（部位 / 数值 / 套装引用）
  affixes.json     词缀池（10 种）
  sets.json        套装与 2/4 件效果（mods / attackMode / artMode）
  skills.json      功法（招式/心法/神通，16 部）
  talents.json     天赋树（3 分支 × 3 节点）
```

**统一修饰（Effect 聚合）**：设计文档的「统一效果 DSL」落地为 TS 类型 `Mods`（12 个修饰键）+ `effects.ts` 的 `aggregateMods()`——装备基座、词缀、套装阶梯、心法（按等级缩放）、天赋全部汇入同一 `Mods`，再经 `calcStats()` 结合职业基础/成长/境界倍率得到最终 `Stats`。攻击模式由 `resolveAttackMode()` 求值：**套装 4 件改写 > 主修招式（需职业匹配）> 职业默认招式**。

**待办**：设计文档规划的 JSON 效果 DSL（`on_equip_count(6)` 这类触发器字符串）+ 单一 Effect 解释器未落地，当前为编译期强类型的 TS 函数实现（更简单直接，但加新套装需改代码而非纯加配置）。

## 五、战斗系统实现

### 5.1 实体模型
- 传统 OOP：`entities.ts` 中 `Player` / 怪物用 class 持有 Phaser Sprite 与状态（连击段数、攻击冷却、受击硬直等），非组件式。

### 5.2 攻击模式（AttackMode）
玩家唯一攻击键触发当前 `AttackMode`，由 `resolveAttackMode()` 求值。当前已实现 10 种：

```
melee_arc（近战扇形三连斩）  whirlwind（360°横扫）  flying_sword（穿透飞剑）
flying_sword_burst（飞剑齐射）  magic_bolt（爆炸火弹）  frost_nova（冰环减速）
frost_nova_burst（玄冰爆发）  thunder_chain（雷链跳跃）  sword_array（万剑归宗剑阵）  giant_sword（巨剑术）
```

每种模式在 `DungeonScene` 中对应一段索敌 + 投射物/范围判定逻辑（未做成设计文档的「纯配置 + 投射物行为注册表」，新增模式需在场景中加分支）。

### 5.3 伤害管线（纯函数 `core.ts::calcDamage`）
```
攻击×倍率 → 会心判定(×1.6) → ±10% 浮动 → 减防御 → 保底 1 点
```
词缀/套装/心法/天赋的加成已在 `calcStats()` 阶段聚合进 `atk/crit` 等最终属性，战斗时直接取用。

### 5.4 敌人与队友 AI
- 状态机 + 优先级：`idle → pursue → attack(range/cd) → flee/heal → special`，怪物在 `monsters.json` 配 `ai: melee | ranged | boss` + 参数。
- 队友 AI 复用同一套，站位按职业（剑修近战贴身 / 仙子远程保距），响应玩家指令。

### 5.5 关卡生成（`levelgen.ts`）
- 自研网格拼接：50×60 格（每格 16px），四类地块（岩石实心 / 地面 / 水域减速 / 石柱障碍），多房间 + 通道 + 合并实心碰撞盒（`wallRects`）做 AABB 碰撞。
- 种子化随机：自研 `mulberry32`（`core.ts::makeRng`），未引入 `seedrandom` 库。

## 六、局外系统实现要点

- **装备实例** `EquipItem`：`{ uid, baseId, quality, affixes[], enh, named, setId }`，词缀生成时按池与权重 roll 定并持久化；含名器（程序命名 + 数值提升）、机缘词缀、强化 +1~+5。
- **功法/天赋**：已学列表 + 等级 + 槽位装配；配装方案 ×5（装备 + 功法装配 + 天赋一键切换）。
- **NPC 系统**：好感度阶段（陌生→相识→友好→信赖→至交）、送礼（按喜好翻倍）、任务（通用 Quest + 进度/完成/奖励）、商店折扣（友好 9 折 / 信赖 8 折）、道友入队。
- **动态内容**（`lore.ts`）：程序化生成名器名、机缘套装（无尽妖域，上限 12 套）、无名古卷心法，运行时注册进配置表。
- **存档**：`localStorage` 单 key `xiuxian_save_v1`，当前 `SAVE_VERSION=5` 带迁移链；战后／切场景自动存档；本地榜单独立存储（`xiuxian_records_v1`）。动态 PRS 的 current-schema 记录已实施严格交叉校验，legacy 记录仅走兼容路径，非法／显式不兼容记录隔离而不影响整档；该工程事实不等同于 QA 独立签收或发布门完成。防作弊在 Web 单机范围不做强校验。

**待办**：设计规划 IndexedDB 存存档主体（装备实例多时体积）未落地。

## 七、性能与包体

**现状**：
- 贴图：`public/sprites/*.png` 散图，未打图集；`textures.ts` 提供程序化像素兜底（外部 PNG 缺失时回退）。
- 掉落物/投射物用数组 + `Phaser.GameObjects` 手动管理，未见独立对象池 Group（DungeonScene 中 `drops[]` 数组复用 Sprite）。
- 物理：战斗判定用几何距离 / 扇形 / AABB 手工计算（`levelgen.ts` 的 wallRects + 距离判定），未用 Arcade 全碰撞做伤害。
- 音频：`public/audio/*.mp3`，BGM 循环、音效一次性，缺失静音兜底。
- 开机画面：静态 `title_bg.png` + 可选 `title_bg.mp4` 视频背景（缺失自动回退）。
- 移动端：`touch-action: none` 锁滚动 + safe-area 适配。

**待办**（设计规划未落地）：
- 纹理图集（TexturePacker）合并与显存控制。
- 资源分包 / lazy load（首包目标 <5MB；历史单包 zip 记录约 6.8MB，不代表当前 PRS 候选包体）。
- PWA manifest（可加桌面图标）。
- 低端机动态降特效（60fps → 30fps）。
- 对象池化投射物/飘字。

## 十二、设计 vs 现状差异清单（技术债）

| 设计文档原规划 | 实际现状 | 建议 |
|---|---|---|
| 设计分辨率 750×1334 | 360×640 | 已定，文档已同步 |
| 存档 IndexedDB（主体） | localStorage 单 key | 装备实例多时再迁 |
| 独立 Store 事件总线 | state.ts 直连 DOM | 够用则不改 |
| 轻 ECS 组件式实体 | 传统 class | 够用则不改 |
| 效果 DSL（JSON 触发器 + 解释器） | TS 强类型聚合函数 | 新套装仍要写代码，可评估是否值得上 DSL |
| 攻击模式「配置 + 投射物注册表」 | 场景内分支逻辑 | 加新攻击模式需改 DungeonScene |
| 纹理图集 | 散图 PNG | 数量不多，暂可不打 |
| 资源分包 / 首包 <5MB | 历史单包记录约 6.8MB | 当前候选包体与商店上传需另行绑定证据 |
| webm/ogg 双格式音频 | 仅 mp3 | iOS Safari 兼容性需验证 |
| PWA manifest | 无 | 低优先级 |
| ESLint + Prettier | 无 | 建议补，成本低 |
| Vitest 单测 + tests/ | 已有覆盖；默认 file-parallel 稳定性未闭环 | 先由 Task #6 解决模块图稳定性，再补齐未签收的核心回归／烟雾证据 |
| scripts/sim 平衡模拟器 | 无 | 数值膨胀前补 |
| 低端机动态降档 | 无 | 视真机反馈 |
