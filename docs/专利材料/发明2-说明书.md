# 说明书

**发明名称**：一种基于统一修饰聚合的攻击形态动态求值方法

---

## 技术领域

本发明涉及计算机游戏软件技术领域，具体涉及一种在移动端竖屏单手操作场景下，将多来源修饰归一化为统一修饰向量、并按优先级链实时求值角色攻击形态的方法，使单一操作键即可承载复杂 Build 体系。

---

## 背景技术

随着移动端游戏的普及，竖屏单手操作的 ARPG（动作角色扮演）与 Roguelike 类游戏日益增多。这类游戏一方面受限于移动端屏幕与单手操作，可用操作键极少（通常仅一个攻击键与一个移动摇杆）；另一方面又追求深度的"Build"（角色构筑）体系（涵盖装备、词缀、套装、心法、天赋等多维度属性来源）。现有技术方案存在以下缺陷：

（1）**操作维度与 Build 复杂度矛盾**。传统做法要么为每种攻击形态分配独立按键，在仅一个攻击键的竖屏场景下挤占屏幕、误操作率高；要么将攻击形态固定为单一形态，牺牲 Build 深度与可玩性。

（2）**多来源修饰缺乏统一抽象**。装备基座、词缀、套装、心法、天赋各自携带不同属性，传统实现常为每一类来源编写一套取值与合并逻辑，来源间耦合严重，难以扩展新的属性来源或新的攻击形态。

（3）**攻击形态切换散落于战斗主流程**。形态决定逻辑常与战斗主循环耦合，新增一种攻击形态需改动多处代码，违背数据驱动原则，维护成本高、易引入缺陷。

因此，亟需一种能够在仅单一攻击键的移动端场景下，将多来源异质修饰归一化为可被统一计算的抽象，并以数据驱动、优先级可配置的方式实时求值攻击形态，且新增形态无需改动主战斗流程的技术方案。

---

## 发明内容

### 1. 发明目的

本发明的目的在于克服上述现有技术的不足，提供一种基于统一修饰聚合的攻击形态动态求值方法，使得：

- 在仅单一攻击键的移动端场景下，角色攻击形态可随 Build（装备/词缀/套装/心法/天赋）自由变化；
- 多来源、异质的修饰被归一化为统一修饰向量，消除来源间耦合；
- 攻击形态以数据驱动、优先级可配置的方式实时求值，新增攻击形态不改动主战斗流程；
- 套装可同时改写普攻攻击形态与神通形态，增强 Build 表达力。

### 2. 技术方案

为实现上述目的，本发明采用如下技术方案：

一种基于统一修饰聚合的攻击形态动态求值方法，包括以下步骤：

**步骤 A，定义统一修饰向量**。定义包含固定键集合的统一修饰向量 `Mods`，所有属性来源经同一抽象被归一化到该向量的固定键上，所述统一修饰向量包含攻击、防御、速度、会心、气血及各项百分比加成共十二个键。

**步骤 B，多来源修饰归一化聚合**。遍历装备基座（含强化）与词缀、套装阶梯效果、心法（按功法等级缩放）与天赋等多来源修饰，将其各自数值经同一累加函数累加到步骤 A 所定义的统一修饰向量，产出聚合后的统一修饰。所有来源共用相同的写入路径，无来源分支特判。

**步骤 C，攻击形态优先级链求值**。依据"套装触发效果优先于主修招式、主修招式优先于职业默认形态"的优先级链，从聚合后的统一修饰中解析当前攻击形态。具体地，依次检查已装备套装是否以达件数阈值为条件改写攻击形态（最高优先），否则检查主修招式是否匹配当前职业并携带攻击形态，否则回退至职业默认形态，从而得到由单一攻击键触发的最终攻击形态。

**步骤 D，神通形态同步求值**。套装触发效果在改写普攻攻击形态的同时，还可依据件数阈值改写神通形态，以同一套解析链路产出大招形态，二者由同一配置与同一求值逻辑驱动。

**步骤 E，数据驱动扩展**。攻击形态与套装/招式效果均以配置数据登记于配置表与枚举中；新增攻击形态或新增修饰来源时仅需在配置表或枚举中登记，无需改动主战斗流程。

### 3. 有益效果

与现有技术相比，本发明具有如下有益效果：

（1）移动端竖屏单键操作即可承载多种（如十种）攻击形态，将操作维度与 Build 深度解耦；

（2）多来源修饰被统一为 `Mods` 向量并经单一聚合函数累加，消除来源耦合，扩展新来源零成本；

（3）攻击形态采用优先级链加数据驱动求值，新增形态不改主流程，符合数据驱动原则、降低维护成本；

（4）套装可同时改写普攻与神通形态并以件数阈值触发，为 Build 表达提供强数据驱动机制。

## 具体实施方式

以下结合附图与一个具体实施例（基于 TypeScript 实现，应用于一款竖屏像素风修仙 Roguelike 网页游戏）对本发明作进一步详细说明。应当理解，此处所描述的具体实施方式仅用于解释本发明，并不用于限定本发明的保护范围。

### 实施例 1：统一修饰向量定义

本发明将所有来源共用的修饰抽象为固定键集合的统一修饰向量 `Mods`，并定义十种攻击形态枚举 `AttackMode`：

```ts
// 所有来源共用的统一修饰（Effect DSL）
export interface Mods {
  atk:number; def:number; speed:number; crit:number; maxHp:number
  atkPct:number; defPct:number; hpPct:number
  aspd:number; lifesteal:number; skillPct:number; cdPct:number
}
export function emptyMods(): Mods {
  return { atk:0,def:0,speed:0,crit:0,maxHp:0,
           atkPct:0,defPct:0,hpPct:0,aspd:0,lifesteal:0,skillPct:0,cdPct:0 }
}
export type AttackMode = 'melee_arc'|'whirlwind'|'flying_sword'|'flying_sword_burst'
  |'magic_bolt'|'frost_nova'|'frost_nova_burst'|'thunder_chain'|'sword_array'|'giant_sword'
```

### 实施例 2：多来源归一化聚合

本发明通过单一聚合函数 `aggregateMods`，将装备基座（含强化）与词缀、套装阶梯效果、心法（按功法等级缩放）、天赋等所有来源经同一 `addMod` 累加函数写入 `Mods` 向量：

```ts
// 汇总所有来源的修饰为统一向量
export function aggregateMods(s: GameState): Mods {
  const mods = emptyMods()
  // 装备基座（含强化）+ 词缀
  for (const key of Object.keys(s.equipment) as SlotKey[]) {
    const it = s.equipment[key]; if (!it) continue
    const mult = enhMult(it)
    addMod(mods,'atk',Math.round(it.atk*mult))
    addMod(mods,'def',Math.round(it.def*mult))
    addMod(mods,'speed',Math.round(it.speed*mult))
    addMod(mods,'crit', it.crit + 0.005*(it.enh??0))
    addMod(mods,'maxHp',Math.round(it.maxHp*mult))
    for (const af of it.affixes) addMod(mods, af.stat, af.value)
  }
  // 套装阶梯效果
  for (const setId of equippedSetIds(s)) {
    const count = setPieceCount(s, setId)
    for (const b of SETS[setId].bonuses)
      if (count>=b.count && b.mods)
        for (const [k,v] of Object.entries(b.mods)) addMod(mods, k as ModKey, v as number)
  }
  // 心法（按功法等级缩放）
  for (const id of s.skillSlots.minds) {
    if (!id) continue
    const m = mindModsAt(id, s.skills[id]??1)
    for (const [k,v] of Object.entries(m)) addMod(mods, k as ModKey, v as number)
  }
  // 天赋
  const tm = talentMods(s)
  for (const [k,v] of Object.entries(tm)) addMod(mods, k as ModKey, v as number)
  return mods
}
```

由于所有来源共用同一向量与同一累加函数，新增属性来源时只需在其对应分支调用 `addMod`，无需为来源编写独立的合并逻辑。

### 实施例 3：攻击形态优先级链求值

本发明依据优先级链实时求值当前攻击形态：套装改写最高优先，其次为主修招式（需职业匹配），最后回退至职业默认形态；套装同时可改写神通形态：

```ts
// 攻击形态解析：套装 4 件改写 > 主修招式(需职业匹配) > 职业默认
export function resolveAttackMode(s: GameState): AttackMode {
  for (const setId of equippedSetIds(s)) {           // ① 套装最高优先
    const count = setPieceCount(s, setId)
    for (const b of SETS[setId].bonuses)
      if (b.attackMode && count>=b.count) return b.attackMode
  }
  if (styleMatchesClass(s)) {                          // ② 主修招式
    const def = SKILLS.get(s.skillSlots.style!)
    if (def?.attackMode) return def.attackMode
  }
  return classDefaultMode(s)                           // ③ 职业默认
}
// 套装同时改写神通形态（如凡人套 4 件 → 大庚剑阵）
export function resolveSetArtMode(s: GameState): ArtMode | null {
  for (const setId of equippedSetIds(s)) {
    const count = setPieceCount(s, setId)
    for (const b of SETS[setId].bonuses)
      if (b.artMode && count>=b.count) return b.artMode
  }
  return null
}
```

### 实施例 4：数据驱动的形态登记

攻击形态与套装/招式效果均以配置数据登记，新增攻击形态时只需在配置表或枚举中登记，无需改动主战斗流程：

```ts
// 套装 4 件效果可直接改写攻击形态（数据驱动，无需改主流程）
interface SetBonus { count:number; mods?:Partial<Mods>; attackMode?:AttackMode; artMode?:ArtMode; desc:string }
interface SetDef { id:string; name:string; pieces:string[]; bonuses:SetBonus[] }
// 招式定义携带 attackMode，装配即生效
interface SkillDef { id:string; name:string; type:SkillType; class:SkillClass
  attackMode?:AttackMode; power?:number; cd?:number; artMode?:ArtMode; mods?:Partial<Mods>; desc:string }
```

### 实施例 5：单键触发与形态承载

在竖屏单手操作场景下，玩家仅以单一攻击键触发攻击。该攻击键在运行时调用 `resolveAttackMode` 取得由优先级链求值得出的当前攻击形态，从而以单一指令承载全部 Build 形态；当玩家切换装备、套装、招式或天赋时，聚合结果与最终形态自动随之变化，无需任何操作键的重新布局。

上述五个实施例共同实现了权利要求 1 所限定的"定义—聚合—求值—同步—扩展"完整方法，并揭示了从属权利要求 2~5 所进一步限定的各项技术特征。

### 应用场景说明

本发明可广泛应用于移动端竖屏单手操作的 ARPG、Roguelike、放置类与卡牌类游戏的角色攻击/技能形态系统，以及任何需要在有限操作键条件下以单一指令承载多形态、并将多来源属性归一化统一计算的计算机应用场景。
