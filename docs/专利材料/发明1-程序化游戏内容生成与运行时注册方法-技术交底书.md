# 技术交底书（发明 1）

## 发明名称
一种游戏内容的程序化生成与运行时动态注册方法

## 一、技术领域
本发明涉及计算机游戏软件领域，具体涉及一种在运行时基于词池与规则模板程序化生成游戏内容（装备套装、功法心法、名器）并将生成内容动态注册至静态配置表、随存档持久化与读档重建的方法。

## 二、背景技术
### 2.1 现有技术的缺陷
1. **静态配置表内容有限**：传统游戏（如 Diablo 类 ARPG、Roguelike）的装备、套装、技能均预先由策划在配置表中手工定义。内容扩展需要策划手工编写大量数据并重新发布版本，成本高、迭代慢，且难以支撑"无尽"类玩法的无限内容需求。
2. **生成内容与静态内容割裂**：部分游戏采用程序化生成（如随机词缀），但生成物通常仅作为"临时实例"存在，与静态配置表解析链路不一致，导致生成内容难以参与统一数值计算、存档与图鉴系统。
3. **存档无法承载生成内容**：当游戏内容在运行时被无限扩展后，传统的"仅保存玩家状态"的存档方案无法重建这些动态内容，导致读档后生成物丢失或数值错乱。

### 2.2 本发明要解决的问题
- 如何在**不修改代码、不重新发布版本**的前提下，使游戏内容（套装/心法/名器）可无限扩展；
- 如何使**程序化生成的内容**与**静态配置内容**走同一条解析与数值计算链路；
- 如何使生成内容**随玩家存档持久化并在读档时精确重建**，且不污染原始静态配置。

## 三、发明内容
### 3.1 发明目的
提供一种游戏内容的程序化生成与运行时动态注册方法，使游戏在运行时基于词池+规则模板生成新的套装/心法/名器，并将其动态注册进静态配置表参与统一解析，且生成结果随存档持久化、读档重建，从而在内容无限扩展的同时保持数值计算、存档、图鉴系统的一致性。

### 3.2 技术方案
本发明包括如下步骤：

**步骤 A：词池与规则模板定义**
预置多个词池（套装主题词、功法前后缀、装备槽位后缀、修饰数值区间）与规则模板（套装=4 部件基座+2/4 件阶梯加成；心法=1~2 条随机数值加成）。

**步骤 B：程序化生成内容项**
基于种子随机数（mulberry32 等确定性随机）从词池抽取并填充规则模板，生成：
- 机缘套装（含 4 件装备基座与 2/4 件阶梯 `mods`）；
- 无名古卷心法（1~2 条随机 `mods`）；
- 名器（前缀+槽位后缀随机命名）。

**步骤 C：运行时动态注册至静态配置表**
将生成结果注入全局静态配置表（`SETS`、`ITEM_BASES`、`SKILLS`），使后续解析、数值聚合、掉落、图鉴均"无感"地把它当作普通静态内容处理。

**步骤 D：随存档持久化**
将生成内容作为玩家存档的一部分序列化保存（而非仅保存引用），使内容归属该玩家存档。

**步骤 E：读档时重建并重新注册**
加载存档时，从存档反序列化生成内容，并再次执行步骤 C 的注册，使运行期配置表恢复至存档时状态。

**步骤 F：无尽模式"现世"策略（防膨胀）**
在无尽模式中按概率触发生成；采用"**补全优先于新建**"策略（已有套装时高概率沿用其中之一，而非无限新建），并对动态套装数量设上限（如 12 套），控制数值膨胀。

### 3.3 有益效果
1. 游戏内容可在**不发布新版本**的情况下无限扩展，显著降低内容运营成本；
2. 生成内容与静态内容**共用同一套解析与数值聚合链路**（`Mods`/`SETS`/`SKILLS`），无割裂、无特殊分支；
3. 生成内容**随存档持久化、读档精确重建**，玩家进度不丢失；
4. 种子化随机保证生成结果可复现，便于测试与排错；
5. "补全优先 + 数量上限"策略在内容扩展与数值平衡之间取得可控折中。

### 实施例 1：词池与程序化生成（对应 `src/lore.ts`）
```ts
// 套装主题词池
const SET_THEMES = ['青元','玄骨','虚天','魔银','惊蛰', /* … */ ]
// 阶梯修饰候选（min, max）
const SET_MOD_POOL: Array<[ModKey, number, number]> = [
  ['atkPct',0.10,0.18], ['defPct',0.12,0.20], ['hpPct',0.10,0.18],
  ['crit',0.03,0.06], ['aspd',0.05,0.10], ['skillPct',0.10,0.18],
  ['lifesteal',0.03,0.06], ['speed',6,12], ['cdPct',0.06,0.12],
]
// 由种子随机数生成一套机缘套装（4 件基座 + 2/4 件阶梯效果）
export function genDynamicSet(rng, seq, existing): DynamicSetRecord {
  const used = new Set(existing.map(r => r.set.name.replace(/套$/,'') ))
  const free = SET_THEMES.filter(t => !used.has(t))
  const theme = free.length>0 ? pick(rng,free) : pick(rng,SET_THEMES)+seq
  const setId = `set_dy${seq}`
  const tier = 1 + Math.min(0.5, seq*0.06)        // 越往后生成的基座越强
  const bases = SET_PIECE_SLOTS.map(slot => { /* 按槽位生成基座数值 */ })
  const m2 = rollSetMods(rng, ri(rng,1,2), 1)
  const m4 = rollSetMods(rng, 2, 1.8)
  const set: SetDef = { id:setId, name:`${theme}套`, pieces:bases.map(b=>b.id),
    bonuses:[ {count:2,mods:m2,desc:`2件：${modsDesc(m2)}`},
              {count:4,mods:m4,desc:`4件：${modsDesc(m4)}`} ] }
  return { set, bases }
}
```

### 实施例 2：运行时动态注册（对应 `src/lore.ts:registerDynamicContent`）
```ts
// 将存档中的动态内容注入静态配置表，使其与静态内容统一解析
export function registerDynamicContent(sets, skills) {
  for (const rec of sets ?? []) {
    if (!rec?.set?.id) continue
    if (!SETS[rec.set.id]) SETS[rec.set.id] = rec.set        // 注册进套装表
    for (const base of rec.bases ?? []) {
      if (!base?.id || ITEM_BASE_MAP.has(base.id)) continue
      base.set = rec.set.id
      ITEM_BASES.push(base)                                  // 注册进装备基座表
      ITEM_BASE_MAP.set(base.id, base)
    }
  }
  for (const sk of skills ?? []) {
    if (sk?.id && !SKILLS.has(sk.id)) SKILLS.set(sk.id, sk)   // 注册进功法表
  }
}
```

### 实施例 3：随存档持久化与读档重建（对应 `src/state.ts`）
```ts
// GameState 中容纳动态内容（归属玩家存档）
interface GameState {
  // …
  dynamicSets: DynamicSetRecord[]   // 机缘套装（运行时注册进 SETS）
  dynamicSkills: SkillDef[]         // 无名古卷功法（运行时注册进 SKILLS）
}
// 读档：重建并注册动态内容
export function loadGame(): GameState {
  const parsed = JSON.parse(localStorage.getItem(SAVE_KEY)!)
  if (parsed.version === SAVE_VERSION) {
    const s = parsed as unknown as GameState
    // …规范化装备/库存…
    s.dynamicSets = s.dynamicSets ?? []
    s.dynamicSkills = s.dynamicSkills ?? []
    registerDynamicContent(s.dynamicSets, s.dynamicSkills)   // 关键：读档重建
    return s
  }
  if (typeof parsed.version==='number' && parsed.version<SAVE_VERSION) return migrate(parsed)
  return newGame()
}
```

### 实施例 4：无尽模式现世策略（对应 `src/scenes/DungeonScene.ts:pickDynamicSetId`）
```ts
// 无尽妖域机缘套装：优先补齐已有套装，否则生成新套（上限 12 套）
private pickDynamicSetId(): string {
  const sets = this.state.dynamicSets ?? []
  if (sets.length>0 && (sets.length>=12 || this.rng()<0.6)) {
    return sets[randInt(this.rng,0,sets.length-1)].set.id   // 补全优先于新建
  }
  const rec = genDynamicSet(this.rng, sets.length+1, sets)  // 新建
  this.state.dynamicSets = [...sets, rec]
  registerDynamicContent([rec], [])
  toast(`天机降临！机缘套装【${rec.set.name}】现世`, '#ffd54a')
  return rec.set.id
}
```

### 实施例 5：种子确定性（对应 `src/core.ts:makeRng`）
```ts
// mulberry32 种子随机：同种子 → 同序列，保证生成可复现（便于测试）
export function makeRng(seed: number) {
  let a = seed >>> 0
  return function () {
    a |= 0; a = (a + 0x6d2b79f5) | 0
    let t = Math.imul(a ^ (a >>> 15), 1 | a)
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296
  }
}
```

## 六、权利要求书（草案）
1. 一种游戏内容的程序化生成与运行时动态注册方法，其特征在于，包括：基于预置的词池与规则模板，利用种子随机数程序化生成游戏内容项；将所述游戏内容项动态注册至游戏的静态配置表中，以使所述游戏内容项与静态配置内容经由同一解析与数值聚合链路被处理；将所述游戏内容项随玩家存档序列化持久化；以及在加载所述玩家存档时，从存档反序列化所述游戏内容项并重新执行所述动态注册。
2. 根据权利要求 1 所述的方法，其特征在于，所述游戏内容项包括装备套装、功法心法与名器中的至少一种；其中装备套装由若干装备基座与按件数触发的阶梯加成构成。
3. 根据权利要求 1 所述的方法，其特征在于，所述动态注册包括：将套装写入套装配置表、将装备基座追加至装备基座表、将功法写入功法配置表，且注册前进行去重判断以避免重复写入。
4. 根据权利要求 1 所述的方法，其特征在于，还包括无尽模式的现世策略：当已存在动态内容时，以高于新建的概率沿用已有动态内容之一，并对动态内容数量设定上限以抑制数值膨胀。
5. 根据权利要求 1 所述的方法，其特征在于，所述种子随机数为确定性随机函数，使得相同种子产生相同的生成序列，从而支持生成结果的可复现与自动化测试。
6. 一种计算机可读存储介质，其上存储有计算机程序，该程序被处理器执行时实现权利要求 1~5 任一项所述的方法。

## 七、与现有技术的区别点（查新关注）
- 现有随机生成多为"临时实例"，本发明强调**生成物注册进静态配置表并参与统一 `Mods` 数值聚合**；
- 现有存档仅存玩家状态，本发明**存档即容纳并能在读档精确重建生成内容**；
- "补全优先于新建 + 数量上限"的**现世策略**为内容扩展与数值平衡提供可控机制。
