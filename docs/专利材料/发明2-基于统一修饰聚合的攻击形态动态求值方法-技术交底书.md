# 技术交底书（发明 2）

## 发明名称
一种基于统一修饰聚合的攻击形态动态求值方法

## 一、技术领域
本发明涉及计算机游戏软件领域，具体涉及一种在移动端竖屏单手操作场景下，将多来源修饰归一化为统一修饰向量、并按优先级链实时求值角色攻击形态的方法，使单一操作键即可承载复杂 Build 体系。

## 二、背景技术
### 2.1 现有技术的缺陷
1. **操作维度与 Build 复杂度矛盾**：移动端竖屏单手场景下，可用操作键极少（通常仅一个攻击键 + 一个移动摇杆），而现代 ARPG/Roguelike 的 Build 体系（装备/词缀/套装/心法/天赋）极为复杂。传统做法要么为每种形态分配独立按键（挤占屏幕、误操作高），要么固定单一形态（牺牲 Build 深度）。
2. **多来源修饰缺乏统一抽象**：装备基座、词缀、套装、心法、天赋各自携带不同属性，传统实现常为每类来源写一套取值与合并逻辑，耦合严重、难以扩展新来源或新形态。
3. **攻击形态切换散落在主流程**：形态决定逻辑常与战斗主循环耦合，新增一种攻击形态需改动多处代码，违背数据驱动原则。

### 2.2 本发明要解决的问题
- 如何在**仅单一攻击键**的移动端场景下，让角色攻击形态随 Build 自由变化；
- 如何将**多来源、异质的修饰**归一化为可被统一计算的抽象；
- 如何以**数据驱动、优先级可配置**的方式实时求值攻击形态，新增形态不改动主流程。

## 三、发明内容
### 3.1 发明目的
提供一种基于统一修饰聚合的攻击形态动态求值方法，将装备/词缀/套装/心法/天赋的修饰归一化为统一修饰向量 `Mods`，并按"套装 4 件改写 > 主修招式 > 职业默认"的优先级链实时求值当前攻击形态，从而以单一操作键承载完整 Build 体系，且攻击形态可数据驱动扩展。

### 3.2 技术方案
**步骤 A：定义统一修饰向量 `Mods`**
将所有属性来源抽象为固定键集合的向量（atk/def/speed/crit/maxHp 及 atkPct/defPct/hpPct/aspd/lifesteal/skillPct/cdPct 共 12 键）。

**步骤 B：多来源修饰归一化聚合**
遍历装备基座（含强化）+词缀、套装阶梯效果、心法（按功法等级缩放）、天赋，将各自数值累加到同一 `Mods` 向量，产出聚合后的统一修饰。

**步骤 C：攻击形态优先级链求值**
依据"套装 4 件改写 > 主修招式（需职业匹配）> 职业默认"的优先级，从聚合结果中解析当前攻击形态（AttackMode，含 10 种：近战弧击/旋风/飞剑/飞剑爆/法弹/冰环/冰爆/雷链/剑阵/巨剑）。

**步骤 D：神通形态同步求值**
套装可同时改写神通形态（ArtMode），以同一套解析链路产出大招形态。

**步骤 E：数据驱动扩展**
新增攻击形态或来源只需在配置表/枚举中登记，无需改动主战斗流程。

### 3.3 有益效果
1. 移动端竖屏**单键操作**即可承载 10 种攻击形态，操作维度与 Build 深度解耦；
2. 多来源修饰**统一为 `Mods` 向量**，消除来源耦合，扩展新来源零成本；
3. 攻击形态**优先级链 + 数据驱动**，新增形态不改主流程；
4. 套装可同时改写普攻与神通形态，Build 表达力更强。

## 五、具体实施方式
### 实施例 1：统一修饰向量定义（对应 `src/data.ts`）
```ts
// 所有来源共用的统一修饰（Effect DSL）
export interface Mods {
  atk:number; def:number; speed:number; crit:number; maxHp:number
  atkPct:number; defPct:number; hpPct:number
  aspd:number; lifesteal:number; skillPct:number; cdPct:number
}
export function emptyMods(): Mods {
  return { atk:0,def:0,speed:0,crit:0,maxHp:0,
           atkPct:0,defPct:0,hpPct:0,aspd:0,lifesteal:0,skillPct:0,cdPct:0 }
}
export type AttackMode = 'melee_arc'|'whirlwind'|'flying_sword'|'flying_sword_burst'
  |'magic_bolt'|'frost_nova'|'frost_nova_burst'|'thunder_chain'|'sword_array'|'giant_sword'
```

### 实施例 2：多来源归一化聚合（对应 `src/effects.ts:aggregateMods`）
```ts
// 汇总所有来源的修饰为统一向量
export function aggregateMods(s: GameState): Mods {
  const mods = emptyMods()
  // 装备基座（含强化）+ 词缀
  for (const key of Object.keys(s.equipment) as SlotKey[]) {
    const it = s.equipment[key]; if (!it) continue
    const mult = enhMult(it)
    addMod(mods,'atk',Math.round(it.atk*mult))
    addMod(mods,'def',Math.round(it.def*mult))
    addMod(mods,'speed',Math.round(it.speed*mult))
    addMod(mods,'crit', it.crit + 0.005*(it.enh??0))
    addMod(mods,'maxHp',Math.round(it.maxHp*mult))
    for (const af of it.affixes) addMod(mods, af.stat, af.value)
  }
  // 套装阶梯效果
  for (const setId of equippedSetIds(s)) {
    const count = setPieceCount(s, setId)
    for (const b of SETS[setId].bonuses)
      if (count>=b.count && b.mods)
        for (const [k,v] of Object.entries(b.mods)) addMod(mods, k as ModKey, v as number)
  }
  // 心法（按功法等级缩放）
  for (const id of s.skillSlots.minds) {
    if (!id) continue
    const m = mindModsAt(id, s.skills[id]??1)
    for (const [k,v] of Object.entries(m)) addMod(mods, k as ModKey, v as number)
  }
  // 天赋
  const tm = talentMods(s)
  for (const [k,v] of Object.entries(tm)) addMod(mods, k as ModKey, v as number)
  return mods
}
```

### 实施例 3：攻击形态优先级链求值（对应 `src/effects.ts:resolveAttackMode`）
```ts
// 攻击形态解析：套装 4 件改写 > 主修招式(需职业匹配) > 职业默认
export function resolveAttackMode(s: GameState): AttackMode {
  for (const setId of equippedSetIds(s)) {           // ① 套装最高优先
    const count = setPieceCount(s, setId)
    for (const b of SETS[setId].bonuses)
      if (b.attackMode && count>=b.count) return b.attackMode
  }
  if (styleMatchesClass(s)) {                          // ② 主修招式
    const def = SKILLS.get(s.skillSlots.style!)
    if (def?.attackMode) return def.attackMode
  }
  return classDefaultMode(s)                           // ③ 职业默认
}
// 套装同时改写神通形态（如凡人套 4 件 → 大庚剑阵）
export function resolveSetArtMode(s: GameState): ArtMode | null {
  for (const setId of equippedSetIds(s)) {
    const count = setPieceCount(s, setId)
    for (const b of SETS[setId].bonuses)
      if (b.artMode && count>=b.count) return b.artMode
  }
  return null
}
```

## 六、权利要求书（草案）
1. 一种基于统一修饰聚合的攻击形态动态求值方法，其特征在于，包括：定义包含固定键集合的统一修饰向量；将来自装备、词缀、套装、心法与天赋的多来源修饰归一化累加到所述统一修饰向量，得到聚合修饰；以及依据优先级链从所述聚合修饰实时求值当前攻击形态，所述优先级链为：套装触发效果优先于主修招式、主修招式优先于职业默认形态。
2. 根据权利要求 1 所述的方法，其特征在于，所述统一修饰向量包含攻击、防御、速度、会心、气血及各项百分比加成共十二个键，所有来源经同一累加函数写入所述向量。
3. 根据权利要求 1 所述的方法，其特征在于，所述套装触发效果能够同时改写普攻攻击形态与神通形态，且改写以套装件数达阈值为条件。
4. 根据权利要求 1 所述的方法，其特征在于，所述攻击形态与套装效果以配置数据登记，新增攻击形态时不改动主战斗流程，实现数据驱动扩展。
5. 根据权利要求 1 所述的方法，其特征在于，应用于移动端竖屏单手操作场景，玩家以单一攻击键触发由所述优先级链求值得出的当前攻击形态。
6. 一种计算机可读存储介质，其上存储有计算机程序，该程序被处理器执行时实现权利要求 1~5 任一项所述的方法。

## 七、与现有技术的区别点（查新关注）
- 现有方案多为"每形态独立按键"或"固定形态"，本发明以**统一 `Mods` 向量 + 优先级链**实现单键多形态；
- 现有修饰合并常为**每来源一套分支逻辑**，本发明统一为**单一聚合函数 + 固定键向量**；
- **套装可同时改写普攻与神通形态**并以件数阈值触发，为 Build 表达提供数据驱动机制。
