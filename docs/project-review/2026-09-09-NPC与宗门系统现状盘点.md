## 0. 一句话结论

NPC 侧有 **4 套互不相通的实体模型**（固定 NPC / 程序化 NPC / 弟子×2 轨），宗门侧有 **2 套建筑升级实现** 与 **2 套弟子集合**。功能量已经很足（14 建筑、6 AI 宗门、7 外交行动、8 灵兽、20 固定 NPC），但**数据模型的分裂**是当前最大的结构性债务，比"功能不够"更值得优先处理。

## 2. NPC 体系：四套模型

### 2.1 固定 NPC（`NpcDef` + `NpcState`）— 20 位

`src/npc-data.ts:137` `NPC_DEFS`

| 项 | 值 |
|---|---|
| 数量 | **20 位** |
| 角色 15 类 | wanderer×2、sect_elder×2、blacksmith×2、arena_master×2、alchemist×2，scout / scholar / rival / merchant / innkeeper / hermit / healer / elder / city_lord / champion 各 1 |
| 地点分布 | 青冥城 6 · 宗门 6 · 大世界 4 · 洞府 2 · 擂台 2 |
| 名单 | 玄清子、陆青鸢、萧天衡、钱万三、苏婉清、雷震、独孤剑、药尘、铁锤、王婆、周道玄、丹阳子、欧冶子、书灵、武狂、陈奉、云游道人、无名老叟、风影、冷无缺 |
| 初始境界 | baseRealm 0~5（元婴→合体档） |
| 修炼速度 | cultSpeed 0.5（商人）~3（陆青鸢） |
| 贴图 | **20 位全部是 `npc_junior` 占位**，真实形象由 `npc-sprite-gen.ts` 按 `appearanceSeed` 程序化生成 |
| 故事线 | `STORIES` **5 条**：长老的心愿、道友的羁绊、城主的考验、宿敌的觉悟、隐士的传承（覆盖 5/20 位） |
| 关系档位 | 6 档：hostile / neutral / acquaintance / friendly / trusted / sworn |

`NpcState` 运行时字段：realm、level(0~9)、exp、favor、storyStage、storyProgress、lastInteract、alive、chronicle（阅历 30 条）、程序化外观 4 件套（appearanceSeed / procGender / procDaoPath / procPhysique）。

成长：每小时按 `cultSpeed` 累加经验，满 10 级触发突破判定（`npcBreakthroughChance`）。

> ⚠️ 固定 NPC **没有装备与功法字段**。今天新增的 `sectNpcProfile()`（`npc-progression.ts:656`）按 id 哈希为它们**派生**一套档案（装备四件 + 功法四门 + 战力），**不写入存档**，仅用于详情面板与切磋判定。

### 2.2 程序化 NPC（`ProceduralNpc`）— 无限生成

`src/procedural-npc.ts`

| 项 | 值 |
|---|---|
| 场上活跃上限 | `MAX_ACTIVE_NPCS = 25` |
| 激活距离 | `NPC_REFRESH_DISTANCE = 600`（判定用 ×2 = 1200） |
| 补员 | 每次缺额补 2 个，随机方位 200~550 距离 |
| 移动 | 活跃 30% 概率移动 / 离屏 5%（仍在活动，仅低频） |
| 生成维度 | 姓名（姓池 + 男女名池）、性别、年龄、境界、体质、职业、性格、出身、道途、志向、当前目的、隐秘、三层故事（表面/中层/深层） |

字段（60~100 行）：`inventory`、`equipment`（旧占位串，兼容保留）、`skills`、`gear`（真实四件）、`loadout`（功法四槽）、`skillLevels`、`cultivation`、`cultivationDays`、`lastGrowthAt`、`breakthroughs`、`power`、`morality`、`location`、`relations`、`schedule`、`eventLog`。

### 2.3 修为档案（`npc-progression.ts`，2026-09-09 新增）

把「只按境界套公式 + 装备占位串 + 功法写死 4 个 id」换成三维度驱动：

- **修为**：境界 / 等级 / 突破次数，每重境界 +18%（玩家 +12%）
- **经历**：体质（异灵根 攻×1.26、修行×1.8）、道途（剑道攻 / 体修血防 / 法修会心）、出身（世家嫡子装备品阶 +1）、职业、心性、隐秘（身怀重宝装备 +1 品）
- **时间**：道行年数 = 年岁×0.55 + 突破×2 + 在世天数×0.03，每 100 年 +40%（封顶 +60%）

装备 → 真实四件 `EquipItem`（品质 / 强化 / 档位由修为+出身+职业+隐秘决定），`uid` 前缀 `npcgear_`，`isNpcOwnedItem()` 拦截流入玩家背包。
功法 → 按道途取真实技能池，门数 1→4 随境界，修炼等级 1~5 且 `upgrades[lv-1].mods` 生效。

**强度曲线**（战力公式 `血*0.35 + 攻*6 + 防*4 + 身法*2 + 会心*300 + 神通威力*90`）：

| 境界 | NPC 战力 | 玩家基准 | 组队倍率 |
|---|---|---|---|
| 练气 | 631 | 623 | 0.95 |
| 金丹 | 4,201 | 2,390 | 1.19 |
| 元婴 | 7,192 | 3,686 | 1.24 |
| 化神 | 12,587 | 5,257 | 1.37 |

时间成长：`WorldScene.update` 按苍玄历总天数 diff 节流调 `tickNpcCultivation()`，跨越一个历日即修行（升级 / 突破 / 重铸装备 / 补录功法）。

### 2.5 灵兽（`beast-data.ts`）

8 物种：幽冥狼 / 玄甲龟 / 灵狐（common）、烈焰熊 / 雷霆雕 / 冰霜蟒（rare）、赤焰麒麟（epic）、幼龙（legendary）

### 3.3 AI 宗门与外交

- **5 种性格**：aggressive / diplomatic / isolationist / expansionist / mercantile

## 5. 问题清单（按严重度）

### P0 · 弟子双轨两套集合、两套类型

| | 轨 A | 轨 B |
|---|---|---|
| 存储 | `sect.disciples: Disciple[]`（`sect-data.ts:63`） | `state.disciples: DiscipleData[]`（`state.ts:137`） |
| 类型 | `disciple-data.ts:69` `Disciple` | `disciple-system.ts:9` `DiscipleData` |
| 关键字段 | 灵根 / 天赋 / 阶位 / 装备 / 闭关 / 切磋 / 忠诚 / 心情 | 特长 / 培养侧重 / 忠诚度 / 心情 / 任务 / 周贡献 |
| 写入方 | `disciple-system.ts:160`、`ui.ts:260`、`SectScene.ts:1489/1548` | `disciple-system.ts:132`（recruitDisciple） |
| 消费方 | SectScene、SectWarScene、**diplomacy.ts（宗门战力）** | WorldScene 招募、sect-management 职位效果、**sect-war / annual-events（宗门战力）** |

**后果**：`diplomacy.ts:66` 用 `sect.disciples.length`、`sect-war.ts:53` 用 `state.disciples` 计算同一件事——**宗门战力存在两套口径**，且玩家在两个界面看到的弟子数可能不一致。招募是同一个入口写两个数组（`disciple-system.ts:132` 与 `:160`），但**没有同步删除**，`diplomacy.ts:369` 只从 `sect.disciples` 删战损。

### P1 · NPC 四套模型互不相通

固定 NPC（NpcState）/ 程序化 NPC（ProceduralNpc）/ 弟子（Disciple）/ 宗门弟子（DiscipleData）——**只有程序化 NPC 有修为档案**，固定 NPC 靠 id 哈希派生（不入库、不成长），**弟子两套都没有装备与功法**。结果是：宗门弟子战力是纯公式值，与 NPC 档案的强度体系脱节。

### P1 · 建筑升级两套实现

- `SectScene.ts:1253` 自有 `upgradeBuilding()`：走 `sect-data.ts` 的 `buildingUpgradeCost`，直接扣 `sect.resources`
- `sect-building-v2.ts:62` `upgradeBuilding()`：另一套成本与判定

`SectScene` **没有 import** `sect-building-v2`。同一栋建筑在两个场景里升级，成本与约束可能不一致。

### P2 · 内容覆盖不足

- 20 位固定 NPC **共用 `npc_junior` 贴图**（靠程序化形象区分，但资源层面是同一个 key）
- 故事线 **5/20** 覆盖，其余 15 位只有通用对话
- 固定 NPC 的 `hasShop` / 送礼等_flag_ 分布零散，无统一配置表

### P2 · 已知测试缺陷

- `tests/npc-diplomacy.test.ts` **flaky**：`updateNpcGrowth` 用 `Date.now()/60000` 播种，奇遇事件按分钟随机命中。单独跑 83/83 通过，全量跑偶发失败，**勿误判为回归**。

## 6. 建议的处理顺序

| 优先级 | 事项 | 说明 |
|---|---|---|
| 1 | 弟子合轨 | 选定 `Disciple` 为真源（字段更全、有装备与战斗属性），`DiscipleData` 降级为派生视图；`recruitDisciple` 单点写入，`diplomacy` / `sect-war` / `annual-events` 统一走 `calcSectPower(state)` |
| 2 | 修为档案下沉到弟子 | 复用 `npc-progression.ts` 的 `forgeNpcGear` / `buildNpcLoadout` / `buildNpcStats`，让弟子也有真实装备与功法（弟子是宗门战力的主体，目前是纯数值） |
| 3 | 建筑升级合并 | `SectScene` 改调用 `sect-building-v2.upgradeBuilding`，删除自有实现 |
| 4 | 固定 NPC 补齐 | 剩余 15 位补故事线；贴图 key 按角色分化 |
| 5 | flaky 修复 | `updateNpcGrowth` 改用 `state` 内的确定性计数器播种，而非 `Date.now()/60000` |

> 1→3 均为数据层收敛，不涉及美术资源，可在不新增任何资产的前提下显著提升一致性与可维护性。
